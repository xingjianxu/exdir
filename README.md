# exdir

一个追求 **紧凑界面** 的 Windows 文件管理器，功能目标对标 [Directory Opus](https://www.gpsoft.com.au/)。
技术栈 **WinUI 3 + Windows App SDK + C#**，非打包（unpackaged）部署。

## 界面

```
┌────────────────────────────────────────────────────────────────────┐
│ ☰  文件 编辑 查看 转到 工具 帮助      当前目录名        － □ ✕      │  顶部菜单栏
├────────────────────────────────────────────────────────────────────┤
│ C: ▢  D: ▢                              Desktop Documents ⋯        │  title 栏
├───────────┬──┬─────────────────────────────────────────────────────┤
│ 文件夹    │  │ ← → ↑ ⟳  C:\Users\xingjian                            │
│  主目录   │  │ ┌ xingjian ┐ ┌ 此电脑 ┐ +                            │
│  云存储   │  │  名称        修改日期      类型        大小          │
│  此电脑   │  │  .cache      9/10 19:37   文件夹                     │
└───────────┴──┴─────────────────────────────────────────────────────┘
```

* **顶部菜单栏**：左侧菜单、中间当前目录名、最右侧系统窗口按钮。
* **title 栏**：左对齐显示磁盘（本地/网络/可移动/光驱），右对齐显示固定的常用目录与快捷菜单。
* **侧边栏**：用户主目录、云存储（同步根目录）、各磁盘的文件夹树，展开时按需加载。
* **主内容区**：支持 1 或 2 个文件窗格；每个窗格有独立标签页，标签内为详细信息列表。

## 功能现状

已实现：自定义标题栏与窗口按钮、磁盘条、固定目录（可拖放新增 / 拖拽排序）、侧边栏文件夹树（懒加载）、
单/双窗格、多标签页（标签条紧凑、顶到窗格顶部）、详细信息列表（可就地展开目录、点列头排序、多选、
双击进入、真实外壳图标、云同步状态列、列宽可拖动 / 自适应）、
前进/后退/上一级历史、可编辑路径框（面包屑 + 就地编辑）、显示隐藏文件 / 显示扩展名 /
文件夹优先、底部状态栏（项数 / 选中摘要 / 卷容量）、文件列表区的**系统右键菜单**
（资源管理器同款，含 7-Zip / Git / VS Code 等第三方扩展；空白处为目录背景菜单）、
**设置窗口**（「配置 → 设置…」，独立窗口、左导航 + 右侧 Windows 11 风格设置卡片、改动即时生效，

真实压缩包文件行右键还有「使用 7-Zip 打开」与「解压到下载文件夹」——前者交给系统装的 7-Zip，
后者把整包解到 `Downloads\<包名>\` 并弹一条带「打开目录」的提示）、
会话与窗口位置持久化、完整快捷键、**命令行调用**（`exdir [path]`，已在运行时转给已有实例并在新标签页打开）、
**在线更新**（启动时后台查 GitHub Release，「帮助 → 检查更新…」也可手动查；发现新版本在窗口顶部提示，
点「立即更新」下载校验后退出、自动替换并重启，见下面「在线更新」一节）。

## 单窗口 + 常驻托盘

点窗口右上角的关闭按钮（或 `Alt+F4`）**只是把窗口隐藏到通知区域**，进程与已打开的窗格、标签页、
目录缓存全部继续活着，所以再打开是一瞬间的事：

* 左键单击托盘图标（或双击 exe）→ 把窗口叫回来；右键托盘图标 → 「显示主窗口 / 退出 exdir」；
* 菜单「文件 → 隐藏到托盘」也能手动藏起来；
* 托盘已驻留时再双击一次 exe 不会起第二个进程，只是把已有窗口叫出来（单实例）；
* **只有「文件 → 退出」或托盘菜单里的「退出 exdir」会真的结束进程**（日志：`%LOCALAPPDATA%\exdir\exdir.log`）。

## 在线更新

菜单 **「帮助 → 检查更新…」** 可以随时查一次 GitHub 上的最新 Release；默认还会在启动几秒后在后台查一次
（设置「启动 → 启动时自动检查更新」，默认开）。

发现新版本只在窗口**顶部弹一条提示条**，**不会自己下载或替换任何文件** —— 点「立即更新」才打开更新窗口：
里面显示当前 / 最新版本与发行说明，点「立即更新」下载发布包（带进度、可取消），
再点「重启并完成更新」：exdir 退出，一个后台脚本把安装目录里的文件换成新的，然后自动重启 exdir。

* 下载包按 GitHub 给出的 SHA256 校验，不符就放弃这次更新；
* **设置与「最新访问」记录不在安装目录里，升级不会丢**；
* 不是发布版安装目录（缺 `build-info.txt`）、安装目录不可写、或系统里没有 Windows PowerShell 时，
  只提供「打开发布页」手动下载 —— exdir 不会提权（提权起来连拖放都用不了）；
* 回归：`pwsh -NoProfile -File tools\test-update.ps1`（用本机 mock feed 冒充 GitHub，
  安装目录是 `dist` 的临时副本，所以动不到你正在用的那份 exdir）。

## 命令行

```powershell
exdir                      # 在已有窗口里打开**当前工作目录**（没在运行就直接启动一个窗口）
exdir D:\projects          # 打开指定目录
exdir D:\projects\a.txt    # 打开文件所在目录并选中它
```

* **已在运行的 exdir 会收到请求**：活动窗格里新开标签页打开；窗口藏着就先唤回；
  已经在该目录里就不重复开新标签页；路径不存在则当前标签页显示「无法打开」。
* 不带路径参数时用的是**本进程**的工作目录，所以从终端里 `cd` 到某个目录再敲 `exdir` 就是打开它；
  双击 exe / 点任务栏图标时的工作目录是程序目录或系统目录，这种情形（不是用户想去的地方）
  只把窗口叫到前台、不动当前浏览位置。
* 单实例：第二次启动不会多出一个托盘图标，也不会多出一份会话去覆盖 `config.json`。
* 回归：`pwsh -NoProfile -File tools\test-command-line.ps1`。

## 构建与运行

前置：.NET SDK 8.0+（本机用 10.0.401 编译 net8.0）、Windows 10 1809+。

```powershell
# Debug 构建
dotnet build exdir.csproj -c Debug -p:Platform=x64

# 运行
.\bin\x64\Debug\net8.0-windows10.0.19041.0\win-x64\exdir.exe

# Release 产物（自包含，输出到 dist\win-x64）
pwsh -NoProfile -File tools\publish.ps1
```

> 注意：**不要用 `dotnet publish`**，它会丢掉 XAML 编译产物导致启动失败，原因见 [`AGENTS.md`](AGENTS.md)。

## 配置文件

```
%USERPROFILE%\.config\exdir\config.json   设置与会话（窗口位置、双窗格、标签页、固定目录…）
%LOCALAPPDATA%\exdir\exdir.log           运行日志与异常
```

配置放在用户主目录（设了 `XDG_CONFIG_HOME` 时以它为准）；从旧版本升级时，
`%LOCALAPPDATA%\exdir\settings.json` 会在首次启动被自动搬到新位置。日志仍在 `%LOCALAPPDATA%`。
